## 1. 파일 위치

| 범위 | 경로 | 적용 대상 |
|---|---|---|
| 개인 | `~/.claude/skills/{이름}/SKILL.md` | 내 모든 프로젝트 |
| 프로젝트 | `{프로젝트}/.claude/skills/{이름}/SKILL.md` | 그 프로젝트만 |
| 플러그인 | `{플러그인}/skills/{이름}/SKILL.md` | 플러그인 설치한 곳 |

이 저장소는 `skills/` 에 두고 `~/.claude/skills` 정션 링크로 개인 범위에 태운다.
그래서 **한 벌만 관리하면서 전역으로 쓴다.**

폴더 이름이 슬래시 명령이 된다. `skills/write-post/` → `/write-post`.

프로젝트 컨벤션(이 저장소는 이렇게 짠다)은 스킬이 아니라 그 프로젝트의
`CLAUDE.md` 에 넣는다. 스킬에 하드코딩하면 다른 프로젝트에서 못 쓴다.

## 2. frontmatter 전체 필드

```yaml
---
name: my-skill
description: 무엇을 하고 언제 쓰는지
disable-model-invocation: true
allowed-tools: Read Grep
---
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `name` | ✅ | 폴더 이름과 같아야 한다. 다르면 인식이 꼬인다 |
| `description` | ✅ | 트리거. 3장 참고 |
| `disable-model-invocation` | | `true` 면 Claude 가 알아서 부르지 못하고 `/명령` 으로만 실행 |
| `allowed-tools` | | 이 스킬이 쓸 도구를 미리 승인. 권한 확인 창이 줄어든다 |

### `disable-model-invocation` 을 켜야 하는 경우

되돌리기 어렵거나 바깥으로 나가는 동작이 들어있을 때.

- 배포, 푸시, 커밋
- 파일 삭제, 덮어쓰기
- 메일·메시지 전송

이런 스킬이 자동으로 불려오면 사고가 난다. **명시적으로 부를 때만** 돌게 한다.

### `allowed-tools` 사용

공백으로 구분한다. 도구 이름만 쓰거나, 인자 패턴까지 좁힐 수 있다.

```yaml
allowed-tools: Read Grep
allowed-tools: Bash(git add *) Bash(git commit *) Bash(git status *)
```

스킬 폴더 경로가 필요하면 `${CLAUDE_SKILL_DIR}` 를 쓴다. 개인·프로젝트·플러그인
어디에 설치되든 알아서 풀린다.

```yaml
allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/render.sh *)
```

## 3. description 작성법

**여기가 트리거다.** 본문이 아무리 좋아도 description 이 애매하면 안 불려온다.

### 공식

```
{무엇을 하는지 — 동작을 나열} + {언제 쓰는지 — 사용자가 칠 법한 표현}
```

### 나쁜 예 → 좋은 예

```yaml
# 나쁨: 명사구. 언제 쓸지가 없다
description: PDF 처리 유틸리티

# 좋음: 동작 + 트리거 조건
description: PDF 읽기·텍스트/표 추출·병합·분할·회전·워터마크·암호화·OCR.
  .pdf 파일이 언급되거나 PDF 출력이 필요할 때 사용.
```

```yaml
# 나쁨: 나만 아는 말
description: 케이스 스터디 생성

# 좋음: 실제 발화를 넣음
description: 포트폴리오 케이스 스터디 페이지를 만든다. "케이스 스터디 써줘",
  "이 프로젝트 포트폴리오에 올리자", "프로젝트 소개 페이지 만들어" 같은 요청에 사용.
  기존 페이지 수정·재생성 요청("다시 써줘", "톤 바꿔줘")에도 사용.
```

### 넣어야 하는 것

- **실제 발화.** 요약하지 말고 자기가 실제로 쳤던 문장을 그대로
- **말투 변형.** 격식체 / 반말 / 줄임말 전부
- **암묵적 표현.** "이거 자동화 좀" 처럼 스킬 이름이 안 나오는 문장
- **후속 작업 키워드.** "다시", "수정", "업데이트", "이어서"

### 넣지 말 것

- 구현 세부사항 (본문에 쓸 것)
- "항상", "반드시" 같은 강조 — 트리거 정확도를 올리지 않는다
- 다른 스킬과 겹치는 넓은 표현 — 서로 잡아먹는다

## 4. 본문 작성법

### 명령형으로 쓴다

```markdown
# 나쁨
이 스킬은 사용자의 입력을 받아 검증한 다음 결과를 생성합니다.

# 좋음
입력을 검증한다. 필수 필드가 빠졌으면 사용자에게 묻고, 추측하지 않는다.
```

### 이유를 함께 적는다

"항상 X 해라" 는 예외 상황에서 깨진다. "Y 때문에 X 한다" 는 응용된다.

```markdown
# 나쁨
항상 테스트를 먼저 실행하라.

# 좋음
변경 전 상태를 알아야 회귀인지 원래 깨진 건지 구분할 수 있다.
그래서 수정 전에 테스트를 한 번 돌린다.
```

### 과적합시키지 않는다

특정 케이스에만 맞는 규칙을 잔뜩 넣으면, 조금만 달라져도 못 쓴다.
규칙보다 **판단 기준**을 준다.

### 길이

**500줄 이내.** 넘어가면 `references/` 로 뺀다. 이유는 6장 참고.

## 5. 번들 리소스

```
{이름}/
├── SKILL.md
├── references/    # 필요할 때만 읽히는 문서
├── scripts/       # 실행 코드
└── assets/        # 출력에 쓰는 템플릿·이미지
```

| 폴더 | 넣을 것 | 판단 기준 |
|---|---|---|
| `references/` | 상세 규칙, 스펙, 예시 모음 | 매번 필요하진 않은 것 |
| `scripts/` | 매번 다시 짜기 아까운 코드 | 같은 코드를 두 번 이상 생성했다면 |
| `assets/` | 템플릿, 로고, 보일러플레이트 | 결과물에 그대로 들어가는 파일 |

`references/` 파일이 300줄을 넘으면 문서 맨 위에 목차를 단다.
Claude 가 필요한 절만 골라 읽을 수 있게 하기 위해서다.

## 6. 점진적 공개

스킬은 세 단계로 나눠 로드된다. 그래서 긴 참고 문서를 붙여도 평소엔 비용이 없다.

| 단계 | 로드 시점 | 크기 |
|---|---|---|
| 메타데이터 (`name` + `description`) | 항상 | ~100단어 |
| `SKILL.md` 본문 | 트리거됐을 때 | 500줄 이내 |
| `references/` | 본문이 지시했을 때만 | 제한 없음 |

**본문이 길어지면 항상 켜져 있는 비용이 아니라 켜졌을 때의 비용이 커진다.**
그래서 500줄을 기준으로 삼고, 넘으면 references 로 옮긴 뒤 본문에서 링크한다.

## 7. 트리거 검증

만든 다음 반드시 한다. 안 하면 안 만든 것과 같다.

### 불려와야 할 문장 3개

말투를 섞는다.

```
1. (격식) "포트폴리오 케이스 스터디 페이지를 작성해 주세요"
2. (반말) "케이스 스터디 하나 써줘"
3. (암묵) "이 프로젝트도 포트폴리오에 올리게 정리 좀"
```

3번이 제일 중요하다. 스킬 이름이 안 나오는데도 걸려야 진짜 쓸 만한 description 이다.

### 불려오면 안 되는 문장 2개

경계에 있는 것으로 고른다.

```
1. "포트폴리오 사이트 배포해줘"        ← 배포는 이 스킬 일이 아니다
2. "케이스 스터디가 뭐야?"             ← 질문이지 작업 요청이 아니다
```

### 결과별 조치

| 증상 | 원인 | 조치 |
|---|---|---|
| 안 불려온다 | description 에 그 표현이 없다 | 실제 친 문장을 추가 |
| 아무 때나 불려온다 | description 이 너무 넓다 | 범위를 좁히거나 `disable-model-invocation: true` |
| 불려오는데 결과가 별로다 | 본문 절차 문제 | description 말고 **본문**을 고친다 |
| 다른 스킬이 대신 걸린다 | 두 description 이 겹친다 | 둘의 경계를 문장으로 명시 |

## 8. 흔한 실패

| 실패 | 왜 생기나 | 예방 |
|---|---|---|
| 만들어놓고 안 쓴다 | 반복이 아닌 걸 스킬로 만듦 | 3회 규칙을 지킨다 |
| 안 불려온다 | description 을 나만 아는 말로 씀 | 실제 발화를 그대로 넣는다 |
| 결과가 매번 다르다 | 본문이 설명문이라 절차가 없다 | 명령형 + 번호 매긴 단계 |
| 다른 프로젝트에서 못 쓴다 | 특정 저장소 컨벤션을 하드코딩 | 컨벤션은 `CLAUDE.md` 로 분리 |
| 고치기가 무섭다 | 한 스킬이 너무 많은 일을 함 | 하나의 스킬은 하나의 절차만 |
