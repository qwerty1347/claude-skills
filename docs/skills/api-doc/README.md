# /api-doc

## 무엇을 하는가

Laravel 변경분에서 API 명세서를 지정한 양식의 HTML 로 만들어 브라우저로 연다.
화면을 드래그 복사해 Jira 댓글에 붙여넣는 것까지가 용도다.

## 왜 만들었는가

API 를 고칠 때마다 파라미터 표를 손으로 만들어 Jira 에 붙였다.
파라미터가 여러 파일(라우트 · 컨트롤러 · FormRequest)에 흩어져 있어 매번 빠뜨렸고,
붙여넣고 나면 표가 깨져 있었다.

## 어떻게 쓰는가

말로 시켜도 불려오고(`"이 API 명세서 만들어줘"`), `/api-doc` 으로도 부른다.
산출물은 **작업 중인 프로젝트가 아니라 harness 의 `docs/api-docs/`** 에 쌓인다.

## 왜 이렇게 만들었는가

| 판단 | 이유 |
|---|---|
| 마크다운이 아니라 HTML | Jira 댓글이 마크다운을 변환하지 않는다. 표와 색이 살아남아야 붙여넣는 의미가 있다 |
| CSS 를 `assets/doc.css` 로 고정 | 문서마다 색·여백이 달라지면 팀 Jira 댓글이 제각각이 된다. 인라인 `<style>` 로 통째로 넣는다 |
| 산출물을 harness 에 모음 | 작업 repo 에 임시 HTML 이 쌓여 `git status` 가 더러워지는 걸 막는다. 7일 지나면 스스로 지운다 |
| 경로를 스크립트가 계산 | PC 마다 harness 위치가 다르다. `scripts/_paths.ps1` 이 junction 을 역추적하고 `.claude-plugin` 마커로 루트를 찾는다 |
| 전역 스킬 | 여러 Laravel 프로젝트에서 같은 양식을 쓴다. 프로젝트 `CLAUDE.md` 에 두면 매번 복사해야 한다 |
| 변경 이력을 남기지 않음 | 명세서는 현재 코드의 스냅샷이다. 무엇이 바뀌었는지는 git 이 안다. NEW/CHANGED/REMOVED 배지는 만들었다가 걷어냈다 |
| 모르면 묻지 않고 `확인 필요` | `in:e,d` 의 의미처럼 코드에 없는 건 되물어도 답이 안 나온다. 멈추는 대신 표시를 남기고 사용자가 채운다. **추측해서 채우지 않는다**는 원칙은 그대로다 |
| 실패 응답은 대표 1개(`500`) | 상태코드를 다 나열하면 문서가 길어지기만 한다 |
| 오래된 문서 정리를 스크립트가 함 | 모델에게 "패턴 맞는 파일을 지워라" 를 시키지 않는다. 삭제는 결정적이어야 하고, 테스트할 수 있어야 한다. 덕분에 `disable-model-invocation` 없이 자동 호출을 열어둘 수 있다 |

## 함정

- **컨트롤러만 보면 "파라미터 없음" 이 된다.** 파라미터는 대부분 FormRequest 의 `rules()` 에 있다
- **인증은 `Route::group` 상위까지 봐야 한다.** 라우트 한 줄만 보면 미들웨어를 놓친다
- **PowerShell 5.1 은 BOM 없는 UTF-8 을 ANSI 로 읽는다.** `scripts/*.ps1` 은 BOM 을 붙여 저장한다.
  안 그러면 한글 메시지가 `?대뜑媛 ?놁뒿?덈떎` 로 나온다
- **브라우저를 `Start-Process` 로 띄우면 안 된다.** 자식 프로세스가 출력 파이프를 물고 있어
  창을 닫을 때까지 호출이 끝나지 않는다. `cmd /c start` 로 분리한다
- **삭제 조건에서 날짜 파싱이 실패하면 폴더를 통째로 비운다.** 실제로 한 번 그랬다.
  `$stamp` 가 `$null` 로 남으면 `$null -lt [datetime]` 이 참이 된다.
  파싱 실패는 반드시 `return` 으로 빠져나가야 한다

## 검증

- `docs-dir.ps1` 을 서로 다른 두 곳에서 실행 → 둘 다 `harness\docs\api-docs` 로 해석되는 것 확인
  (작업 프로젝트 루트, harness 하위 폴더)
- 7일 정리를 8개 파일로 검증. 15일·8일 전 → 삭제, 경계(7일 전)·최근·오늘 → 유지,
  날짜가 깨진 `2026-13-99_*` 와 패턴 밖 파일 → 유지
- 실제 API 로 문서를 만들어 Jira 댓글에 붙여넣어 표·배지 색이 유지되는지 확인

## 제작 기록

- 산출물 위치를 처음엔 **실행한 프로젝트의 루트**로 잡았다가, 작업 repo 를 건드리지 않는 쪽이
  낫다고 판단해 harness 고정으로 뒤집었다
- 변경 이력 배지(NEW/CHANGED/REMOVED)와 그 CSS 를 만들었다가 전부 제거했다.
  명세서에 이력을 섞으면 "지금 코드가 무엇인지" 가 흐려진다
- "모르면 사용자에게 묻는다" 를 네 군데에 넣었다가 전부 `확인 필요` 표시로 바꿨다.
  되묻느라 멈추면 문서를 못 받는다
- 오래된 문서 정리를 `SKILL.md` 절차(모델이 판단해 삭제)에서 `docs-dir.ps1` 로 옮겼다.
  `allowed-tools` 가 **사전승인 목록**이지 제한 목록이 아니라서, 삭제 수단을 목록에 넣는 것은
  "모델에게 삭제 권한을 상시 부여" 와 같았다. 스크립트로 옮기니 그럴 필요가 없어졌다
